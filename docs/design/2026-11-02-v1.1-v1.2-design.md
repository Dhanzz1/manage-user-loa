# Manage-UserLOA v1.1 and v1.2 design

Status: draft for approval, 2026-11-02 (reviewed; owner questions answered).

## Intent

v1.0 has been tested against a production AD and Exchange Online environment.
v1.1 and v1.2 add cloud sign-in cutoff, a config file, a state journal that
makes Start/End symmetric and re-runnable, and a set of SaaS connectors. The
Zoom and Slack connectors are designed here but ship in v1.3.

There will be **no lab or live-tenant testing** of the new work. The owner wants
to ship it and close it out, but it must still have real value. So the evidence
that the new work is correct is a **fake tenant**: sample data held in memory
that the mocked wrappers read and mutate, so tests can prove round trips,
re-runs and failure handling, not just "the right function was called".

## Goals

- v1.1: remove the Google Workspace and Generic REST connectors; simplify OOO;
  load and validate config from `.psd1`; cut off cloud sign-in after disable.
- v1.2: per-user JSON journal; End restores from it; Start and End both safe
  to re-run; pluggable connector contract; EntraGroups, AddOnLicences,
  Atlassian and HubSpot connectors plus `_Template`.
- v1.3: Zoom and Slack connectors (design in section 8a below).
- A fake-tenant test harness that every new feature is tested against.
- CI that runs the suite on every push.

## Non-goals

- Live or lab validation of anything new.
- Creating or editing Conditional Access policies.
- App-only Graph auth. Graph is delegated, as the operator, interactively.
- Migrating tests to Pester 5.
- Changing v1.0 AD/Exchange behaviour except where this doc says so.

## Anti-goals (failure even if it "works")

- A secret in config, code, journal, console output or test fixtures.
- Any connector issuing an HTTP `DELETE`.
- Removing a licence that carries an Exchange mailbox.
- Changing a group-assigned licence.
- A connector failure blocking or rolling back the core AD/Exchange workflow.
- End silently losing pre-LOA state (journal must be written before the change
  it describes).
- Overwriting an Enabled or Scheduled OOO without `-ForceOOO`.

## Constraints

- PowerShell 5.1+ (Windows PowerShell and pwsh).
- Tests must run on Pester 3.4.0 (the inbox version; the only one installed).
  Existing test style is kept.
- Every external call goes through an `Invoke-LOA*` wrapper so it can be mocked.
- Secrets only via `Microsoft.PowerShell.SecretManagement`.
- Small commits, one feature each; owner sees each diff before it is committed.
- README, CHANGELOG and tests updated with each release.
- `.gitignore` excludes `*.json`; test fixtures need an explicit allow rule.
- Windows PowerShell 5.1: `ConvertFrom-Json` returns PSCustomObject (no
  `-AsHashtable`); always pass `-Depth` to `ConvertTo-Json`. Journal code must
  handle both. Fake tenant mocks return PSCustomObject from JSON reads, not
  hashtables.

## Approaches considered (testing)

| | Approach | Trade-off |
|---|---|---|
| A | Per-call mocks (current style) | Cheap, but cannot show End undoes Start |
| **B** | **Fake tenant: stateful sample data behind the wrappers** | More harness code; proves round trip, re-run and failure paths |
| C | B plus a demo script | Showcase value; ~half a day extra |

**Chosen: B.** The owner picked it because the new work will only ever be
tested this way, so the tests must carry real weight. C was not taken.

## v1.1 design

### 1. Remove Google Workspace and Generic REST

Delete `Invoke-LOAGoogleWorkspaceSuspension`, `Invoke-LOAGenericSaaSAction`,
`Join-LOAApiUrl`, `Invoke-LOASaaSDeactivation`/`Reactivation`, their config
keys, tests, README/docs/example mentions. Workflow step 6 goes away until v1.2
replaces it with the connector runner. CHANGELOG marks it breaking.

### 2. OOO rule

`Resolve-OOOAction`: `-ForceOOO` → Set; Disabled → Set; Unavailable → Skip;
Enabled or Scheduled → ManualReview; anything else → ManualReview.
`OOOSchedulingThreshold` and its message text are removed.

### 3. Config from `.psd1`

- `Start-UserLOA` and `End-UserLOA` gain `-ConfigPath`.
- Resolution order: `-ConfigPath` → `$env:MANAGE_USERLOA_CONFIG` →
  `$env:ProgramData\Manage-UserLOA\config.psd1`. Missing file → throw naming
  all three.
- `Import-LOAConfig` loads via `Import-PowerShellDataFile` into
  `$Script:Config` (so existing code keeps reading `$Script:Config`).
- Validation throws listing every problem at once:
  - required: `LOAOUDistinguishedName`, `DomainController`, `OUStashAttribute`
    (v1.2 adds `JournalPath`);
  - `OUStashAttribute` must match `^extensionAttribute([1-9]|1[0-5])$`;
  - DNs must look like DNs (`^(OU|CN)=`).
- Unknown top-level keys → warning (catches stale Google/REST keys).
- `examples/config.example.ps1` → `examples/config.example.psd1`.
  `config.local.psd1` added to `.gitignore`.
- The in-module `$Script:Config` defaults are removed; there is one source of
  truth, the file.

### 4. Graph connection and sign-in cutoff

- `Connect-LOAServices` also loads `Microsoft.Graph.Authentication`,
  `Microsoft.Graph.Users.Actions`, `Microsoft.Graph.Groups` and connects with
  `Connect-MgGraph -Scopes <needed> -NoWelcome`. If `Get-MgContext` already
  has every needed scope it is reused; otherwise reconnect.
- v1.1 scopes: `User.Read.All`, `User.RevokeSessions.All`, and
  `GroupMember.ReadWrite.All` only when `SignInBlockGroupId` is set.
- Optional config key `SignInBlockGroupId` (object ID of a **cloud-only**
  security group targeted by a CA "Block access" policy the admin creates once;
  README documents this and that it needs Entra ID P1).
- Start order: stash OU → **add to block group (if configured)** → disable AD
  → **revoke sessions** → hide GAL → move → delegate → OOO.
- Failure of the block-group add or of revoke **throws and stops Start**. The
  user may be left disabled but not moved or delegated; that is intended. The
  existing `finally` still prints the AFTER snapshot. Re-running Start is safe
  (stash skipped, disable idempotent, group add skips if already a member).
- Revoke succeeds when the cmdlet returns `$true` or an object whose `Value`
  is `$true`. Anything else, or a throw, is a failure. The fake tenant tests
  both success shapes.
- Without the block group, the summary prints a warning that the user can
  sign in again until Entra Connect syncs the disable (~30 min default).
- End: after enabling AD, remove from the block group if a member. Failure
  here is an `[ERR]` line, not a throw (the user is returning; the operator
  can fix it by hand).
- New wrappers: `Invoke-LOAConnectGraph`, `Invoke-LOAGetMgContext`,
  `Invoke-LOARevokeSignInSession`, `Invoke-LOAGetGroupMember`,
  `Invoke-LOAAddGroupMember`, `Invoke-LOARemoveGroupMember`.

## v1.2 design

### 5. State journal

- Required config key `JournalPath` (a directory). One file per user:
  `<JournalPath>\<upn-lowercase-with-@-as-_at_>.json`. README advises
  restricting the folder ACL to LOA operators.
- Written atomically (temp file + `Move-Item -Force`) after **every** step, so a
  crash mid-run keeps everything done so far. Writes are real file I/O; tests
  use Pester `TestDrive:`.
- Shape (SchemaVersion 1):

  ```text
  SchemaVersion, UserPrincipalName, Status (Active | Closed)
  Start:    { At, Operator, GraphAccount, Runs[] }
  End:      { At, Operator, GraphAccount, Runs[] }
  Captured: { OriginalOU, Enabled, HiddenFromGAL, ADGroups[],
              Licences[], Manager, FullAccessPreExisting, SendAsPreExisting,
              OOO { State, StartTime, EndTime, InternalMessage,
                    ExternalMessage, ExternalAudience } }
  Steps:    { <stepName>: { Status, At, Message } }   # core steps
  ManualTasks: [ instruction, ... ]                   # core ManualTasks
  Connectors: { <Name>: { Captured, Suspend {Status,Message,At},
                          Restore {Status,Message,At}, ManualTasks[] } }
  ```

  `Operator` is `$env:USERDOMAIN\$env:USERNAME`; `GraphAccount` from
  `Get-MgContext`. `ADGroups` and `Licences` are recorded for the audit
  trail; only connectors change them.
- Captured values are written **once**: a re-run of Start never overwrites
  `Captured`, so the pre-LOA truth survives.
- Start behaviour by journal state:
  - none → create, capture, run.
  - Active → reuse; skip steps whose status is Done; retry Failed.
  - Closed → archive as `<name>.<yyyyMMddHHmmss>.closed.json`, start fresh.
- End behaviour by journal state:
  - Active → restore from it; skip steps whose restore is Done; when every core
    step and connector restore is Done/Skipped/NotSupported/ManualTask, set
    Status Closed.
  - Closed → print "already ended" with the journal timestamp, change nothing.
  - none (legacy v1.0/v1.1 LOA) → warn, fall back to v1.1 behaviour (stash OU,
    disable OOO, remove manager delegation), skip connectors with a message.
- Start with an OU stash but no journal (a legacy LOA still in progress, e.g.
  Ana Ruiz) → **throw** before any change: "User is mid-LOA from an older
  version; run End-UserLOA first." Otherwise Start would capture LOA state as
  the pre-LOA truth.
- Manager: End reads the manager from the journal. `-ManagerUPN` becomes
  optional on End when a journal exists (still required for the legacy
  fallback). If supplied and different from the journal → throw, so End never
  removes the wrong person's access.
- Enabled and block group (owner decision): End always re-enables the AD
  account and always removes the user from the sign-in block group, because
  the user is returning. If `Captured.Enabled` was `$false`, or the user was
  already in the block group before LOA, End prints a `[WARN]` naming it and
  records the warning in the journal. The round-trip test for these users
  asserts the warning instead of state equality on those fields.
- Restore rules that change v1.0 behaviour (now possible because state is
  known):
  - OOO: End does **not** restore a captured Enabled or Scheduled OOO. It
    disables OOO and adds a ManualTask: "Previous OOO saved in journal.
    Confirm with the user before re-enabling." Captured Disabled behaves as
    before (End disables OOO).
  - GAL: if the user was already hidden before LOA, End leaves them hidden.
  - Delegation: if the manager already had FullAccess/SendAs before LOA, End
    leaves it. The existing pre-existing warnings are reworded to say this.
- The journal never holds secrets or tokens. A test scans every written
  journal for the fake tenant's secret values.

### 6. `Invoke-LOARestMethod`

- Params: `-Method -Uri -Headers -Body -ContentType -Connector -MaxRetries
  (default 5)`. Body objects are JSON-encoded (`-Depth 10`).
- Calls inner wrapper `Invoke-LOAHttpRequest` (the only place that calls
  `Invoke-RestMethod`), so tests mock one function.
- On 429 or 503: honour `Retry-After` (seconds or HTTP-date); if missing,
  exponential backoff 2, 4, 8... capped at 60 s. Sleeps via `Start-Sleep`
  (mocked). After `MaxRetries`, throw with status, connector and URI.
- Status/headers extracted from both Windows PowerShell (`WebException`) and
  pwsh (`HttpResponseException`) error shapes.
- `DELETE` is rejected by the wrapper itself (throws) — enforces the anti-goal.
- Never writes headers or bodies to output; error messages include method, URI
  and status only.

### 7. Connector contract

- One file per connector in `src/Manage-UserLOA/Connectors/<Name>.ps1`. The
  file, when invoked, returns:

  ```powershell
  @{
      Name    = 'Atlassian'
      Scopes  = @()                       # extra Graph scopes, if any
      Capture = { param($Context) ... }   # returns hashtable saved to journal
      Suspend = { param($Context, $Captured) ... }  # returns result
      Restore = { param($Context, $Captured) ... }  # returns result
  }
  ```

- Result object: `@{ Status = 'Done'|'Skipped'|'NotSupported'|'ManualTask';
  Message = '...'; ManualTasks = @('instruction', ...) }`. A step may be Done
  and still carry ManualTasks (e.g. HubSpot). The runner adds `Failed` when a
  scriptblock throws.
- `$Context`: `UserPrincipalName`, `ADUser` (incl. `Department`), `GraphUserId`,
  `Settings` (that connector's config section), `GetSecret` (scriptblock →
  `Invoke-LOAGetSecret -Name $Settings.SecretName -Vault $Config.SecretVault`),
  `Rest` (scriptblock → `Invoke-LOARestMethod` with `-Connector` pre-filled).
- Config:

  ```powershell
  SecretVault = 'LOA'
  Connectors  = @{
      Atlassian = @{ Enabled = $true; ManagedBy = 'Api'; SecretName = 'LOA-Atlassian'; ... }
  }
  ```

  `ManagedBy` is required for every SaaS connector (not EntraGroups or
  AddOnLicences, which are Graph-native). `'Entra'` → result Skipped with
  "Access to <Name> is managed by an Entra group. Add the group to the
  EntraGroups DepartmentGroups mapping instead."
- Runner `Invoke-LOAConnectors -Phase Start|End` runs after the core
  workflow, in config order. Start: Capture → write journal → Suspend → write
  journal. End: Restore from journal → write journal. Each connector is wrapped
  in try/catch; failure is recorded and printed, never thrown.
- Core failure ("fail closed"; builder recommendation, owner asked for one):
  - Start: if the core workflow throws after the AD disable, connectors
    **still run** (inside the existing `finally`, before the AFTER snapshot),
    then the original error is re-thrown. Cutting access is the safe
    direction. If Start throws before the disable (e.g. config, user lookup,
    block-group add), connectors do not run.
  - End: if the core workflow throws, connector Restore is **skipped** with a
    message. Access is not reopened until identity is restored; re-running
    End retries.
- Re-run: Start skips a connector whose Suspend is Done; End skips one whose
  Restore is Done. Failed is retried.
- `-WhatIf`: connectors are not run; each prints "would run <Name>".
- Loading: module import loads every `Connectors/*.ps1`; only names enabled in
  config run. Unknown connector name in config → validation error.
- Summary: a "Connectors" block after the AFTER snapshot lists each
  connector's status, then a "Manual tasks" block lists every ManualTask with
  its instruction. Both are also in the journal.
- Secret shape per connector is documented in its file header. Secrets are
  SecretManagement `Hashtable` secrets where more than one value is needed.

### 8. Connectors

Each connector file header records the vendor doc URLs used and the date they
were read. Endpoint details below are the owner's spec; the builder confirms
them against current vendor docs while implementing.

**EntraGroups**
- Config: `DepartmentGroups = @{ 'Sales' = @('<groupId>'); '*' = @('<groupId>') }`
  (`'*'` applies to every department).
- Capture: AD `Department` → mapped group IDs → intersect with user's current
  Entra memberships. Journal stores only groups the user was actually in.
- Suspend: remove from each. Restore: re-add each captured group not already
  a member. A group that is on-prem synced cannot be changed via Graph → that
  group is reported as a ManualTask.
- Scope: `GroupMember.ReadWrite.All`.

**AddOnLicences**
- Config: `SkuPartNumbers = @('POWER_BI_PRO', 'VISIOCLIENT', ...)`.
- Capture: user licence assignments + `licenseAssignmentStates` (direct vs
  group) + tenant `subscribedSkus` (part number ↔ SKU ID, service plans,
  units).
- Exchange-bearing = SKU contains a service plan named `EXCHANGE_S_STANDARD`,
  `EXCHANGE_S_ENTERPRISE`, `EXCHANGE_S_DESKLESS` or `EXCHANGE_S_ESSENTIALS`.
  (`EXCHANGE_S_FOUNDATION` gives no mailbox and is ignored.) Such SKUs are
  never removed even if listed; a warning says so.
- Suspend: remove only listed, directly assigned, non-Exchange SKUs. Captured
  `disabledPlans` are saved. Group-assigned listed SKUs → Message reported,
  untouched.
- Restore: re-add captured SKUs with their `disabledPlans`. If a SKU has no
  free units → ManualTask "Free or buy a <SKU> licence, then assign it".
- Scopes: `LicenseAssignment.ReadWrite.All`, `Organization.Read.All`.

**Atlassian** (Org Admin API v2 only)
- Settings: `OrgId`, optional `DirectoryId`. Secret: API key.
- Capture: look up `accountId` by email and `directoryId` (config value or
  lookup). Saved to journal.
- Suspend: `POST .../directories/{directoryId}/users/{accountId}/suspend`.
  Restore: `.../restore`.

**HubSpot** (`/settings/users/2026-09`, version pinned in one constant)
- Secret: private app token.
- Capture: user ID, `roleId`, primary + secondary team IDs, `seatNames`.
- Suspend: `PUT` user with `seatNames = @()`; Done + ManualTask "Deactivate
  <email> in HubSpot Settings > Users & Teams".
- Restore: read seats; for each captured seat, if `remainingSeats` < 1 →
  ManualTask for that seat; otherwise `PUT` captured role, teams and seats.
- Never `DELETE` (also enforced by the REST wrapper).

**_Template**
- Fully commented, no-op. Each scriptblock prints what a real connector
  would do and returns Skipped. Used by README "Writing a connector".

### 8a. v1.3 connectors (not built in v1.2)

Zoom and Slack use the v1.2 connector contract unchanged. Their fake-tenant
data, fixtures and scenarios are added in v1.3.

**Zoom** (Server-to-Server OAuth)
- Secret: hashtable `AccountId`, `ClientId`, `ClientSecret`. Token fetched
  per run via `POST https://zoom.us/oauth/token?grant_type=account_credentials`.
- Capture: user `id`, `type`, and add-on feature settings (e.g. large meeting,
  webinar), plus whether Zoom Phone is enabled.
- Suspend: `PUT /users/{id}/status` `{ action = 'deactivate' }`.
- Restore: `activate`; if captured `type` was 2 → `PATCH /users/{id}`
  `{ type = 2 }` (builder's call: the spec said always 2; patching a user who
  was Basic would consume a licence); re-apply captured add-ons.
- Zoom Phone enabled → ManualTask on both Suspend and Restore.

**Slack** (SCIM)
- Secret: hashtable `ScimToken`, `WebApiToken`.
- Capture: SCIM user by email → ID; channel memberships via Web API
  `users.conversations`.
- Suspend: SCIM `PATCH` `active = false`. Restore: `active = true`, then
  `conversations.invite` per captured channel; `already_in_channel` counts as
  success; any other channel failure → ManualTask listing the channels.
- SCIM unavailable on the plan (vendor's plan error) → NotSupported, with a
  message that SCIM needs Business+ or Enterprise Grid.
- Visibility limits: `users.conversations` only returns channels visible to
  the token, and `conversations.invite` fails for private channels the
  inviter isn't in. Both fall back to ManualTask (Capture records that the
  channel list may be incomplete; Restore lists channels it could not rejoin).
- v1.3 fake tenant adds: Zoom users/settings, Slack users/channels/plan; Sam
  Wu gains Zoom Phone and a Slack workspace on a non-Business+ plan; scenarios
  add plan → NotSupported, Zoom Phone → ManualTask, private channel →
  ManualTask.

### 9. Fake tenant

- `tests/Fakes/FakeTenant.ps1`:
  - `New-LOAFakeTenant` builds `$global:LOAFake` from sample data: AD OUs and
    users, mailbox ACLs and OOO, Entra users/groups/memberships/sessions, SKUs
    with units and service plans, the block group, Graph context, a secret
    vault, and per-vendor records (Atlassian users, HubSpot users/seats/teams).
  - `Register-LOAFakeTenantMocks` mocks every `Invoke-LOA*` wrapper (and
    `Connect-LOAServices`, `Write-Host`, `Start-Sleep`) to read/write that
    state. `Invoke-LOAHttpRequest` is routed by method + host + path to small
    per-vendor handlers whose response bodies come from fixtures.
  - Fault injection: `$global:LOAFake.Faults` keyed by operation, e.g. return
    429 with `Retry-After: 3` twice, or throw once.
  - `Get-LOAFakeUserState -Upn` returns a comparable slice of everything about
    one user across all systems. It excludes things that are one-way by
    design: revoked-session counters, sign-in timestamps and the journal
    itself. The stash attribute is included (empty before and after).
- `tests/Fixtures/<Vendor>/*.json`: response shapes taken from vendor docs.
  `.gitignore` gets `!tests/Fixtures/**/*.json`.
- Sample people: Jane Doe (plain case, Sales, has add-ons, Atlassian and
  HubSpot accounts); Bob Lee (pre-existing Enabled OOO, already hidden from
  GAL, manager already has FullAccess, group-assigned Visio); Ana Ruiz
  (legacy LOA with stash but no journal); Sam Wu (a synced Entra group).
- Scenarios each new feature must cover (minimum):
  - Start → End round trip: `Get-LOAFakeUserState` after End equals before
    Start for Jane and Bob, except Bob's OOO: End disables it, so the test
    asserts the "Previous OOO saved in journal" ManualTask (console summary
    and journal) instead of OOO equality.
  - Seat shortage is its own scenario, not part of a round trip: the fake
    tenant gives Jane's freed HubSpot seat (and a freed add-on licence unit)
    to someone else mid-LOA, and Restore must return a ManualTask.
  - Start twice, End twice: second run changes nothing and reports skips.
  - `-WhatIf`: fake state unchanged.
  - Revoke failure and block-group failure: Start throws, user disabled, not
    moved, no delegation.
  - Config: missing key, bad stash attribute, unknown key warning, unknown
    connector, missing `ManagedBy`.
  - Journal: written after each step (fault mid-run leaves partial journal);
    Captured not overwritten on rerun; Closed archive; legacy fallback; no
    secrets in any journal.
  - REST: 429 with seconds, with HTTP-date, without header; gives up after
    MaxRetries; DELETE rejected.
  - Each connector: happy Suspend/Restore, its specific rules (Exchange SKU
    kept, group-assigned untouched, no seats → ManualTask, synced group →
    ManualTask), and a thrown error is recorded and non-blocking.
  - Revoke: both success shapes (`$true` and `@{ Value = $true }`) pass;
    `$false` and `@{ Value = $false }` fail.
  - `ManagedBy = 'Entra'` → Skipped with the EntraGroups message.

## Decided by the owner

- Delegated, interactive Graph auth.
- Revoke failure stops Start, leaving the user disabled but not moved/delegated.
- Fake tenant (B) as the only test evidence for new work.
- End always re-enables a returning user and removes them from the block
  group, warning if they were disabled or blocked before LOA.
- Connectors fail closed: Start still suspends SaaS if core fails after the
  disable; End skips SaaS restore if core fails (owner asked for a
  recommendation; this is it).
- End disables a captured Enabled/Scheduled OOO and raises a ManualTask
  rather than restoring it.
- Zoom and Slack move to v1.3.
- Revoke success shapes; CI pins Pester 3.4.0; PS 5.1 JSON constraints.
- Everything in the original v1.1/v1.2 spec, including endpoint choices,
  `ManagedBy`, result types and the README note text.
